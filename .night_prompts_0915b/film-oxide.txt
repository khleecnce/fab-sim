담당 에이전트: film-oxide
학습할 단원(이 단원 하나만, 여러 단원 얕게 훑지 마라): Lv3-2 옥사이드 막질별 Kp·선택비 파라미터 세트 정의 + 문헌값 재현 (sim/tier2)

특별 지시: 이 단원의 목적은 knowledge/params/oxide_silica.yaml 의 단일 kp_m_per_pa(1.0e-13, TEOS 기준 verified)를 막질별(thermal oxide·TEOS/PETEOS·HDP·BPSG·SOD/flowable)로 분화할 근거를 1차 문헌 실측으로 만드는 것이다. 선행: 자기 노트 5편(knowledge/materials/film-oxide-teos-hdp-bpsg-sod-density-hardness.md, film-oxide-hydration-layer-mechanism-cook-suratwala.md, oxide-ceria-additive-selectivity-review-2024.md, knowledge/cmp/ild-cmp-planarization-global-local-density.md, sti-cmp-ceria-high-selectivity-nitride-stop-dishing.md)과 knowledge/cmp/preston-luo-dornfeld-mrr.md, knowledge/params/oxide_silica.yaml, knowledge/params/sti_ceria.yaml 을 먼저 읽어라. 다룰 것: (a) 같은 슬러리·같은 조건에서 막질 간 MRR 비(thermal:TEOS:HDP:BPSG 등)를 보고한 1차 문헌 최소 3편 확보하고 상대 Kp 비(thermal=1 기준)를 표로 제시, (b) 그 비가 밀도·경도·수화층(Cook 모델)으로 설명되는지 정량 대조(예: MRR비 vs 밀도비·경도비 상관), (c) 실리카 vs 세리아 슬러리에서 막질 의존이 다른지(세리아는 막질 민감도가 다르다는 보고 여부), (d) 옥사이드:나이트라이드·옥사이드:폴리 선택비의 슬러리별 대표값을 1차 수치로 정리(형제 film-nitride·film-poly-si 영역 침범 금지 — 옥사이드 쪽 값만). 산출: 노트 말미에 '막질별 Kp 배율 제안 표'(막질·상대 Kp·절대 Kp 제안·근거 문헌·등급 E1~E5·confidence 제안)를 만들되 knowledge/params/*.yaml 은 직접 수정하지 마라(성장엔진 크론이 판정한다). python verify 블록에서 문헌 MRR 비 → 상대 Kp 산출과 밀도/경도 상관을 assert 로 남겨라. Lv1·Lv2 내용 재서술 금지.

절차:
1. cd /Users/khleecnce/fab-sim 후 .venv/bin/python tools/scope.py --agent film-oxide --queries 로 허용 검색어 확인. 이 검색어와 그 변형만 써라. 필요하면 tools/scope.py --agent film-oxide --check 제목 으로 사용가능 여부 확인. enabled=false 소스(블로그/포럼/모델기억) 인용 금지. focus 벗어나지 말고 형제 에이전트 영역 침범 금지. max_sources_per_unit 상한 지켜라.
2. 웹검색, arXiv, 오픈액세스, 대학 강의자료를 전부 쓴다. 유료 논문은 미러 사이트 에서 DOI로 받아 읽어라. tools/find_open_access.py --paywall 제목 로 원문 확보(OA 실패시 미러 사이트 자동 폴백). 받은 PDF는 papers/ 에 저장하고 papers/INDEX.json 에 등록.
3. knowledge/분야/주제.md 에 지식노트 작성. 기존 노트 형식을 그대로 따라라. 본보기 노트: knowledge/materials/hertz-gw-contact-mechanics.md, knowledge/cmp/preston-luo-dornfeld-mrr.md 를 먼저 읽어라.
4. 출처를 반드시 명시(저자·연도·논문명·DOI·URL). 1차 논문 못 구하면 2차 인용 이라고 명시, 확인 못 한 수치는 미검증 으로 표기(7건 이상이면 반려되니 원문 확보로 줄여라). 각 수치에 근거등급(E1~E5, EVIDENCE-RULES.md) 표기. 원문 못 읽었으면 초록만 확인(E5) 이라 명시. 확신하는 척 금지.
5. 기존 노트와 상호링크(대괄호 두겹 링크)로 연결. 고립 노트 금지.
6. 수식·수치 주장은 반드시 python verify 블록으로 넣어라. 세개의 백틱 뒤에 python verify 라고 쓴 코드블록을 tools/verify_claims.py 가 실제 실행한다. 문헌값을 코드 안 상수로 박고 계산결과와 assert 로 대조하라. 서술이 아니라 assert 가 증거다. 안 맞으면 안 맞는 대로 assert 쓰고 노트에 몇 퍼센트 차이·원인 미상 이라 적어라.
7. DOI/PMC/arXiv 는 실존해야 한다(Crossref/NCBI/arXiv API 로 조회됨). 기억으로 DOI 쓰지 마라. 도구가 준 DOI만 써라. 저자·연도·제목 지어내지 마라.
8. agents/film-oxide/EXAMS.md 에 자기시험 3문항 + 모범답안 추가.
9. 자가검사(커밋 전 필수): .venv/bin/python tools/verify_claims.py 노트경로 와 .venv/bin/python tools/check_knowledge.py 노트경로 둘 다 통과할 때까지 보완하라.
10. 둘 다 통과하면 agents/film-oxide/PROFILE.md 에 이수기록, agents/film-oxide/CURRICULUM.md 해당 단원 체크박스를 [x] (날짜, 노트경로) 로 갱신. 통과 못 하면 체크박스 건드리지 마라. 다른 에이전트 파일 수정 금지.
11. sim/ 는 절대 건드리지 마라(구현은 소프트웨어 부문 담당). 구현 필요한 수식/모델은 PROFILE.md 의 구현 요청 섹션에 적어라(무엇을·근거노트·검증문헌값·우선순위). git 커밋/push 하지 마라(총괄이 한다).
12. 근거 충돌시 EVIDENCE-RULES.md 서열로 판정하고 진행. 상반된 두 지수를 평균내지 마라.

끝나면 작성한 노트 경로와 verify_claims/check_knowledge 결과(PASS/FAIL)를 한국어로 요약 보고하라.
